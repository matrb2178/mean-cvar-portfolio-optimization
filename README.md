# Mean-CVaR Portfolio Optimization

An R implementation of **Mean-CVaR portfolio optimization** with and without Bitcoin and Ethereum, including efficient frontiers, risk-adjusted portfolio selection, transaction costs, turnover controls, and an out-of-sample backtest against a 1/N benchmark.

The project is designed as an academic and reproducible portfolio-allocation exercise. It is **not investment advice**.

## What the project does

- Downloads adjusted historical prices from Yahoo Finance.
- Aligns all assets on common trading dates before computing arithmetic returns.
- Builds Mean-CVaR efficient frontiers with and without cryptoassets.
- Selects the maximum-STARR portfolio in-sample for descriptive analysis.
- Runs a rolling out-of-sample backtest using only information available at each rebalance date.
- Applies transaction costs and a turnover cap inside the daily return series.
- Compares optimized portfolios with 1/N benchmarks.
- Reports return, volatility, Sharpe, Sortino, VaR, CVaR, STARR, maximum drawdown and Calmar metrics.
- Exports publication-ready figures and CSV tables.

## Main methodological settings

- Historical CVaR / Expected Shortfall confidence level: **95%**.
- Training window: **252 trading days**.
- Rebalancing frequency: **63 trading days** (approximately quarterly).
- Maximum executed turnover per rebalance: **0.80**, defined as the sum of absolute weight changes.
- Transaction-cost assumption: **0.30% of traded notional**, configurable in `main.R`.
- Crypto constraints: individual caps plus a joint BTC+ETH group cap.
- Risk is reported at **daily frequency**; return is annualized for economic interpretation.

## Out-of-sample design

At each rebalance date, the model:

1. Uses only the previous 252 trading days as the training sample.
2. Builds the feasible Mean-CVaR frontier.
3. Selects the portfolio with the highest daily STARR ratio.
4. Applies the turnover constraint relative to the current drifted portfolio.
5. Charges transaction costs on the rebalance date.
6. Evaluates the resulting portfolio over the following approximately 63 trading days.

The daily out-of-sample series is then concatenated across all periods. Drawdown is therefore calculated from the **continuous wealth path** and does not reset at quarterly boundaries.

## How to run

1. Open `mean-cvar-portfolio-optimization.Rproj` in RStudio.
2. Review the user parameters at the top of `main.R`.
3. Run:

```r
source("main.R")
```

The script will create the required `data/` and `output/` directories if needed, download/cache market data, run the optimization and backtest, and export the results.

## Interpretation notes

The in-sample efficient frontier and maximum-STARR allocation use the full historical sample and should be interpreted descriptively. The primary performance evidence is the rolling **out-of-sample** backtest.

The 1/N portfolio with crypto is intentionally shown as a standard naïve benchmark. Because equal weighting across all nine assets assigns more than 15% to BTC+ETH, it is not subject to the same crypto group constraint as the optimized portfolio and should not be interpreted as a feasible point under the optimizer's constraint set.

## Reproducibility

The main historical analysis is deterministic conditional on the selected assets, dates, downloaded adjusted-price history, and parameter settings. The optional actionable-portfolio section is disabled by default because it uses current market prices and is therefore time-dependent.
